# Areas

- capture: Own dropper: capture writers, the store, views; the harness action log
- skills: Org skills read whoami; later skill-driven triggers
- sessions: Org session packages on the mini; retrieval later
- nodes: Directory work surfaces; address is the full path; agent and human share the node
- threads: Org thread/project/task assignment and Workspace surfacing
- clv: The identity seam: clv whoami/env and its subcommands; session ids
- entry: Front door: clv-login, authorized_keys binding, name checks, registration helper, SSH setup
- orchestrate: Org /orchestrate pass: judge and hand off, do not do the thread work
- agents: How agents attach: CLI surface, one SDK wedge, actor vs model account vs DWD
- dwd: signJwt impersonation client; subject switch; not MCP
- workspace: Mail, calendar, tasks, Docs, Sheets as a person
- env: Shared base everyone gets: env-level guidance, settings, installed skills, availability (clv's env scope)
- deploy: deploy-mini; keeping the mini identical to the repo
- user: Own space per person: folder, AI settings and brief, git name (clv's user scope)
- guardrails: House rules in code: AI permission rules, tamper checks, refusals

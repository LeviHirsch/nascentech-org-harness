clv-dwd source_token only refreshes when google-auth says invalid. The on-disk access token can be valid and still 401 IAM (ACCESS_TOKEN_TYPE_UNSUPPORTED). Fix: always refresh before signJwt, or retry once on 401. Dry-run: forced refresh then signJwt 200 from BatchMode. Do not create an SA key. Not a missing-scope bug.

Shipped (2026-08-16): signJwt now retries once on 401 with a force-refreshed source token, and a successful refresh is persisted to disk so the stale token stops failing for the next reader. source_token() gained force_refresh, since c.valid is only a LOCAL expiry check and IAM rejects some locally-valid tokens. Verified from BatchMode on the mini and the retry path fires correctly — but it cannot reach a 200, because the refresh itself dies with 'Reauthentication is needed'. The mini@ refresh token is dead and only a browser consent can mint a new one, so this was never only a code bug. That now exits with an actionable message naming the token path and the likely cause (OAuth app still in Testing = 7-day refresh expiry) instead of dumping a stack trace into a cron log. The dry-run criterion (forced refresh then signJwt 200) stays UNMET until mini@ is re-consented. Not deployed to the mini for that reason.

Requirement (Levi): non-coders get set up terminal-side, register a key, then get in with one command. On 10/2 he pointed at his own setup: "ssh nt and I'm golden… the login is as simple as one terminal command… maybe there is a homebrew tap we set up to get them the .collevity or .clv clientside something or other… such that it gives a way for holding the login creds and setting up the key." And: "What is the log-in flow and how do they 'register a user on the server for the first time'?"

Levi's setup (10/2): Host nt in ~/.ssh/config runs cloudflared as its proxy; cloudflared opens a browser by itself when the Cloudflare session runs out and caches the result, so day to day it is one command (plus an ssh-nt shortcut).

The flow for everyone else:
1. The person pastes the kit's one-line install for their OS (T138); it makes the key and the nt entry and prints an ssh-ed25519 line, which they text to Levi.
2. Levi runs nt-register <name> "<that line>" (T15), inside register-a-person (T103).
3. The person types nt (T139), checks their own name with clv whoami, and lands in their own space (T131).

The kit was built 10/3 in the public repo LeviHirsch/homebrew-tap, folder clv/: clv setup (T138) and clv login with nt as its shortcut (T139), installed under ~/.collevity by a script per OS. Mac is tested (Levi's MacBook Air reached the mini as airtest); Windows (T141) and Linux and Chromebook (T146) still need a real-machine test; a Homebrew formula is optional later (T140).

Exists: clv-login binds a key to a name (8/12); Levi's laptop and phone keys are bound; per-person folders are made at first sign-in; the 8/8 SOP is the model guide.

Gaps (10/2): nameless keys and password login skip identity (T98); any text is accepted as a name (T99); registration has no record (T103); the SOP would create nameless keys (T104); nobody has checked who Cloudflare admits (T102); the fellow's key has no passphrase (T153).

Decided: per-person SSH keys now, a stricter check later (Levi 8/12); identity is read only through clv whoami; Cloudflare stays the way in, through a client kit, with Tailscale as the noted alternative (Levi 10/2). Ruled 10/2: sign-in stays Cloudflare's Google login, about a week per session, with no service tokens (T100); the kit works on any OS ("it has to be agnostic ultimately"). Ruled 10/3: "the middle path at least seems like a good idea": clv is the kit's main command, nt its shortcut, installed under ~/.collevity (T136); the kit is published in the tap repo.

Open: none.

Done when: a fellow on a clean laptop, whatever its OS, runs the one-line install, is registered, and from then on gets in with one command as themselves; each registration is recorded; one removal has been tested.

Manual interim: until T87 lands, each registration's record is Levi's T103 run.

Later: T60 (sign-in at the mini's own keyboard); the stricter check (T126) and the two removal gaps (T145), both in Lock-down.

Intent: everyone gets in with one command as themselves, the way Levi does, and adding or removing a person is a known, recorded step.

Requirement (Levi): non-coders set up terminal-side, register a key, then get in with something like "ssh-nt", ideally without a browser. "What is the log-in flow and how do they 'register a user on the server for the first time'?"

Exists: clv-login binds a key to a name (a forced command, 8/12); Levi's laptop and phone keys are bound; each person's folder is made at first sign-in; two ways in (Cloudflare and Tailscale); the 8/8 SOP is the model setup document.

Gaps (10/2):
- two nameless old keys and password login skip identity (T98);
- any text is accepted as a name (T99);
- registration is a by-hand edit with no record (T103);
- the SOP would create nameless keys (T104);
- nobody has checked who Cloudflare admits (T102).

Decided: per-person SSH keys now, a stricter check later (Levi 8/12); identity is read only through clv whoami.

Open: T100 (the way in, and the browser).

The flow: the person installs the way in and runs the setup kit, then sends their public key → Levi runs register-a-person → the person types ssh nt and sees their own name → they land in their own space (T131).

Done when: every registered person gets in with one command as themselves, each registration is recorded, and one removal has been tested.

Manual interim: until T15 and T87 land, registration is Levi running the T103 flow by hand.

Later: T60 (sign-in at the mini's own keyboard); the stricter check in Lock-down (T126).

Intent: everyone gets in with one command as themselves, and adding or removing a person is a known, recorded step.
